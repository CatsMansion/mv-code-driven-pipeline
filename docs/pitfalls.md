# 踩坑与硬规矩

每条都带**根因**和**判据**。没有根因的条目一律视为谣传，不要写进来。

---

## 1. ⛔ 人物落点：不能用 bbox 中心当 sprite cx

**症状**：某几帧人物只剩一片背景，或脸贴到画布边缘。肉眼逐帧看很难发现（人会盯着画面中心，而人在边缘消失）。

**根因**：引擎的 `sprite` 锚点是**图像中心**，`probe_bbox.py` 量的是**人物 bbox 中心**。
两者相差 `(bbox_cx − img_w/2) × k`。实测偏移 90–300px。

**正解**（`k = sprite_w / img_w`）：

```
face_x = cx − sprite_w/2 + bbox_cx × k
cx     = face_x + (0.5 − bbox_cx / img_w) × sprite_w
```

用 `scripts/snap_cx.py` 算，不要手推。实测案例：目标脸位 700、`hFrac=1.00`、`bbox_cx=370`
→ 正确 `cx=1119.8`；若直接把 `bbox_cx` 当 `cx`，脸会落到 `x=−50`（画布外）。

**判据**：`snap_cx.py --shots` 报出的「脸 x」必须在 `[edge_margin, W−edge_margin]` 内。

---

## 2. ⛔ 遮罩镜头之间只能硬切

**症状**：转场中间出现「十字」——两条方向不同的遮罩同时存在。

**根因**：`xfade` / `wipe` 会把两张画面的遮罩**叠加**。竖带淡入横带的瞬间就是十字。

**正解**：遮罩镜头之间只用**硬切**，或 `black` / `flash`（它们不叠加遮罩）。
真正好看的转场是「从镜头内部长出来的」——A 里的圆 → B 里的同一个圆（iris match-cut），
但那要求两个镜头**共用同一个形状**，不是靠转场滤镜硬接。

---

## 3. ⛔ 遮罩带宽有可读区间：180–720px 才叫「带」

| 宽度 | 读起来是什么 |
|---|---|
| < 120px | 一条线（设计上的闭合，qc 会跳过） |
| **180–720px** | **一条缝 / 一道带（语法成立）** |
| 900–1200px | 已经很勉强，接近"图贴一边" |
| **> 1260px** | **语法失效**：只是把图放在左边，观众读不到"被隔开" |

**推论**：想让画面"更狠"，**不能靠把带加宽**。加宽 = 语法消失。
（这正是递进第一版失败的原因，见 `principles.md` §2。）

---

## 4. ⭐ 带外必须是「暗」，不是「空」

缝外直接填背景色，画面读起来是"一张图贴上去"；填 `bg × 0.46`（混黑）之后，
语义立刻变成「她在暗处，光从缝里进来」，层次就出来了。

**判据**：把画面缩到 25% 看，如果带外和带内亮度差 < 2 档，说明压得不够。

---

## 5. ⛔ 音频时间点一律实测，不抄文档

实测一批数字和原文档的差距（同一首歌，librosa 重跑）：

| 项 | 文档值 | **实测值** |
|---|---|---|
| BPM | 161.5 | **163.99**（全曲在缓慢加速，单值 BPM 本身就是近似） |
| 副歌起点 | 41.96 / 42.26 | **42.72**（前面 41.43–42.33 有 32dB 停顿） |
| 副歌终点 | 66.00 | **66.14**（取 66.09 作为 64 拍整） |
| 1 拍 | 0.3715s | **0.3659s** |

差 0.4s 的强拍，一听就露。**方法**：切段 wav → 60fps 分辨率 RMS 差分取局部极大，
再看 `impacts` 里 strength 最高的 downbeat。

**判据**：段落长度必须能被「拍数 × 拍长」整除。对不上就是时间点错了，不是歌不规整。

---

## 6. ⛔ 递进不是把数字放大

| 做法 | 结果 |
|---|---|
| 带宽 720 → 1120/1400/1920 | 语法被毁（> 1260 就不叫带） |
| 字号 110 → 124、180 → 200 | 大面积溢出、字幕被裁 |
| 带宽 ±8% | 8 拍里 6 拍肉眼无差别 —— **等于没做** |

**能看见的只有三类改动**：景别（hFrac ±15%）、色彩（曝光 / 饱和 / 边色）、
同一位置的**反向动作**（闭合 → 撑开 + 白闪）。

---

## 7. ⛔ 几何预检的判据不是「可见面积占比」

第一版按「人物可见面积 / bbox 面积」报，结果**把所有刻意窄的镜头全报成 bug**。

**正解**：
- 主判据 = **脸是否在遮罩内**
- `min_slit`（默认 120px）以下跳过 —— 那是"闭合"的设计
- 每镜前 `warmup`（默认 0.25s）跳过 —— 遮罩正从 0 张开，边界必然擦过脸
- 面积只在「遮罩已经 900×600 以上、人物可见却 < 25%」时才作为辅助告警

**双对照**（缺一即判据不可用）：

| 对照 | 做法 | 期望 |
|---|---|---|
| 阴性 | 已验收的时间轴 | 全绿，`rc=0` |
| 阳性 | 把某镜遮罩中心挪 60px / 收窄到 360px | 必须报硬伤 |

实测阳性对照：某镜 `center 700→760`、`to 440→360` → 38 帧「人物出遮罩」。
这条 60px 的错**肉眼完全看不出来**，只有几何算得出来。

## 8. 呼吸包络会吃掉边界余量

`v += amp × (low − 0.28) × 2.2` ⇒ 最坏情况遮罩**收窄 `0.616 × amp`**。
如果脸刚好贴边，呼吸会让它在低音区出界 1–2 帧。

`qc_scan.py` 默认**不**计入呼吸（否则会对遮罩张开的头几帧误报），
需要极限严格时加 `--breathe`。两种结论都要在报告里写明用的是哪一种。

## 9. 渲染链路上的死结

| 现象 | 根因 | 处置 |
|---|---|---|
| `Driver does not support the required nvenc API version` | 驱动版本低于 NVENC 要求 | 一律 `--codec x264`，别在这上面耗时间 |
| 渲染 0.4ms/帧但整片仍慢 | 瓶颈是**像素读回**（~45ms/帧），不是绘制 | 优化方向是并行 worker，不是优化场景 |
| 第 0 帧字形不对、后面正常 | 字体没预热，首帧掉回 fallback | `document.fonts.load()` 显式预热全片用到的字 |
| 12fps コマ打ち 看起来没效果 | 它只影响 `breathe` / `sway` 这类微参，没做局部作画时屏幕上几乎看不出来 | 想要"动起来好看"必须有序列帧素材；帧率不是万能药 |
| 中文/日文路径下 ffmpeg 报错 | 滤镜里的 `file=` 参数不能带盘符 | `cwd=<素材目录>` + 相对文件名，输出用绝对路径 |

## 10. 交接包里不要放的东西

| 别放 | 为什么 |
|---|---|
| `fonts/`（200MB+） | 对方脚手架会自动下载；放进去只是让包变大 |
| `node_modules/` | 同上 |
| 原始大图 / 工程中间产物 | 交接要的是"能重跑"，不是"全备份" |
| **任何本地绝对路径** | 推公开仓库前必须扫一遍「本机用户目录」写法（Windows 的盘符+用户目录、POSIX 的 home 路径） |

**必做**：打包后**解包重建验证**（`pack_handover.py` 默认就做），
逐文件 sha256 正反两向对齐 + 在解包目录里跑一次真实命令（如 `qc_scan.py`）。
"包能解开"和"包能跑"是两件事，后者才叫交付。
