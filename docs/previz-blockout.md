# 整片色块预演（previz blockout）—— 花钱生成之前，先把整片跑成 123 秒

> 这一份解决管线里的一个空档：分镜表写完了（阶段 4），生成素材还没出（阶段 3/7）。
> 这时候**没有人知道成片长什么样**：谁在第几秒出现、占多大、底色够不够亮、切点接不接得上。
> 等到素材烧完积分渲出来才发现「顺序不对」，返工成本是全部重来。

做法：**用已有的立绘当人物、用代码渲的色块当场景，把整片按分镜表逐帧跑出来，带原声。**
产物是一支手感和时长都正确的低保真片，不是终稿。它的唯一职责是让人在**花掉第一笔生成积分之前**做判断。

```
分镜表(23格)  ──►  previz 脚本  ──►  previz.mp4 (123.2s / 3696帧 / 带原声)
                                        │
                            看色块 / 位置 / 节奏 / 亮度
                                        │
                                  改分镜表，不改素材
```

## 一、三个必须做对的数

这三条每一条都单独翻过车，都有实测数字。

### 1. 景别校准：用「k 倍画高」，并且人物缩放必须与镜头脱钩

**症状**：分镜表写「近景」，出来的画面是「大半身」；写 1.62 倍人物画高，实测只到 **0.83 倍**。

**两处根因，都是同一个：把人物的尺寸交给了镜头。**

- 人物贴图按场景坐标系画，镜头一推近，人物跟着一起放大 ⇒ **双重放大**。
- 放大后人物超出画框被裁掉，量到的「可见高度」自然比设定小。

**修法**：给每一镜一个**独立于镜头**的 `k`（人物身高 / 画面高 H），贴图按 `k*H` 直接缩到目标像素高，
落地线由 `k` 推出来，保证头顶永远压在上缘：

```python
# k = 人物身高，单位是"H"（画面高）。
# 落地线 base 由 k 反推，不手填：头顶 = base - k*H，让头顶落在上缘外 2%
base = k * H * 1.02
paste_fig(frame, fig_at(pose, tint, k * H), cx * W, base)
```

已标定的四档（1920×1080 实测对位）：

| 景别 | k | 落到 1080 上的人物高 |
|---|---|---|
| 全景（全身进画） | **0.95** | 1026 px |
| 中景（膝上） | **1.70** | 1836 px |
| 中近（腰上） | **2.40** | 2592 px |
| 近景（胸上） | **3.30** | 3564 px |

⛔ **镜头缩放只作用于背景**。人物贴完再让 `cam_crop` 裁背景，两者互不影响：

```python
for pose, cx, k in chars:
    paste_fig(base, fig_at(pose, tint, k * H), cx * W, k * H * 1.02)   # 人物钉死在画面上
frame = cam_crop(scene, z, cxf, cyf)                                   # 镜头只动背景
```

⚠️ 3.3 倍人物高的贴图每帧 resize 会拖死渲染。按**目标像素高**做缓存键：

```python
_cache = {}
def fig_at(pose, tint, figh_px):
    key = (pose, tuple(tint), int(round(figh_px)))
    if key not in _cache:
        rgba = figure(pose, tint)
        s = figh_px / rgba.shape[0]
        _cache[key] = cv2.resize(rgba, (int(rgba.shape[1]*s), int(figh_px)), interpolation=cv2.INTER_AREA)
    return _cache[key]
```

### 2. 音画同步：分镜表里的「镜头空档」必须被显式延展

**症状**：逐格渲染后，42 秒之后画面越来越早，全片少了 **51 帧（1.7 秒）**。

**根因**：分镜表里相邻镜头之间存在**没写进表格的间隙**（本次 4 处，合计 1.71s）。
逐格渲 `[t0, t1]` 再顺序拼接，等于把这些间隙从时间轴上剪掉了 —— 对卡点稿是致命错误，越往后偏得越多。

```
表中：  格A 12.12-17.07 │(空 0.32)│ 格B 17.39-23.80
逐格渲：格A 12.12-17.07 │         │ 格B 一上来就顶到 17.07  ← 之后全程提前
```

**修法**：每格的结束时间延伸到**下一格的开始时间**，最后一格延到全片时长：

```python
fixed = []
for i, s in enumerate(SHOTS):
    nxt = SHOTS[i + 1][1] if i + 1 < len(SHOTS) else TOTAL   # TOTAL = 音频真实时长
    fixed.append((s[0], s[1], nxt) + tuple(s[3:]))
SHOTS = fixed
```

**验收**：`nb_frames` 必须等于 `round(TOTAL*fps)`；再在**每个接缝两侧各抽一帧**核格号。
本次 3696 帧对上（123.272s × 30fps = 3698，差 2 帧在内插误差内），4 个接缝全部落对格。

⛔ 别用「总帧数对得上」当唯一判据 —— 删掉 4 个空档再随机补几帧，总帧数也能对上，但顺序已经错了。
**必须两侧抽帧核格号。**

### 3. 亮度可读性：中位数读出来是「几点钟」的

**症状**：色块按「黄昏末」调好了，渲出来整体读作**深夜**。没有人能说清哪里不对，因为每个色块单看都对。

**根因**：色块的颜色对了，但**整幅的亮度分布**掉了。读起来是几点钟由中位数决定，不由色相决定。

**量法**（采样 37 帧，13–123s 每 3s，**裁掉底部 14% 的字幕带**）：

| | 修前 | 修后 | 判读 |
|---|---|---|---|
| 中位 | **72.5** | **101.0** | 中位 70 出头读作「夜」，95–105 读作「日落后 15 分钟」 |
| 暗部 p10 | 43.1 | 73.0 | p10 低于 50 时暗部会糊成一片 |
| 均值 | 81.8 | 112.3 | 单一均值会被大面积天空骗，只作对照 |
| 亮部 p90 | 134.4 | 172.0 | |

**提亮要改画面层，不是加后期曲线。** 实测有效的三处：

```python
# ① 天空整条色带往上抬（最深一档是主因）
SKY = [(0.00,(18,22,46)), (0.20,(46,40,86)), (0.34,(120,84,110)),
       (0.44,(196,124,90)), (0.50,(150,96,86)), (0.58,(78,56,62))]     # 修前
SKY = [(0.00,(58,70,122)), (0.20,(112,96,152)), (0.34,(190,126,152)),
       (0.44,(255,178,112)), (0.50,(240,150,96)), (0.58,(156,116,110))] # 修后
# ② 地面/建筑基线一起抬：GROUND (52,54,66)→(104,108,126)；CITY (26,30,44)→(54,60,88)
# ③ 人物暗部映射放宽：0.42+0.58*ln → 0.52+0.48*ln
```

⛔ **不要靠统一乘一个亮度系数**。整体乘系数会把已经过曝的格推爆：本次有一格（高调回忆）
p90 到 **305**（8bit 上限外），必须单独压回 224。

**逐格复测是必须的**，因为跑偏的是个别格而不是整体。本次三格单独偏：

| 格 | 问题 | 处理 |
|---|---|---|
| 高调回忆格 | p90 = 305 爆白，中位 229 | 渐变底 (204,196,184)→(150,142,136)，glow 0.35→0.16 ⇒ p90 224 |
| 长走廊全景 | 中位 57.4（上一轮漏提） | 自己的渐变改 (74,84,134)/(152,122,152)/(80,84,108) ⇒ **109.4** |
| 口袋特写 | 中位 66 | 布料渐变 (112,68,50)/(178,108,74)/(92,56,42) ⇒ **92** |

## 二、场景：8 个模板够用

色块场景不需要「画得好」，需要**能把人物放进去并且读得出空间关系**。

| 模板 | 构成 | 用途 |
|---|---|---|
| `corridor` | 一点透视走廊：门列 + 天花梁 + 栏杆 | 楼道戏的主力 |
| `corr1pt` | 极简一点透视（只有地面/墙/顶三条线） | 拉长走路的空镜 |
| `roof` | 天空渐变 + 矮墙 + 栏杆 + 远景楼群剪影 | 天台 |
| `stairs` | 阶梯 + 侧墙 + 高窗光斑 | 楼梯间 |
| `door` | 门框 + 门缝光柱 + 把手剪影 | 推门/偷看特写 |
| `pocket` | 布料纹理 + 口袋鼓包 | 物件特写 |
| `memory` | 高调白底 + 柔光晕 | 回忆/闪回 |
| `obj13` | 全黑 + 自发光物件 | 自持光物件特写 |

**超采样**：场景一律渲到 **1.17 倍**（2240×1260）再让镜头裁，留推拉余量。
`z = 1.0 + 0.075*p`（p 为镜头内进度），推到 1.075 时还剩 8% 余量，不会露边。

```python
def cam_crop(scene, z, cxf, cyf):
    h, w = scene.shape[:2]
    cw, ch = int(w / z), int(h / z)
    x = int(np.clip(cxf * w - cw / 2, 0, w - cw))
    y = int(np.clip(cyf * h - ch / 2, 0, h - ch))
    return cv2.resize(scene[y:y+ch, x:x+cw], (W, H), interpolation=cv2.INTER_AREA)
```

## 三、人物：拿已有立绘做单色剪影

previz 不需要表情和细节，需要**轮廓和体积**。所以：

1. 绿幕立绘抠图 → alpha
2. 映射成单色（每个角色一个色，靠色相区分谁是谁），亮度用对数映射保住体积感：
   `out = tint * (0.52 + 0.48 * log(1+lum)/log(1+255))`
3. 贴图时 `alpha_mul = 0.92`，避免和背景色块硬贴出边

⚠️ 别用纯色平涂。**纯色剪影会丧失前后体积，看不出人物朝向**，渲染出来像纸片。
⚠️ 回忆格不要用冷色（实测冷蓝剪影贴在白底上"像鬼"），改用暖灰。

## 五、这一环的边界（务必和对方说清）

previz **不证明好看**。它只证明：

- 顺序对不对（谁在前谁在后、谁和谁同框）
- 景别对不对（人物占画多高、有没有被切）
- 节奏对不对（4 秒一镜还是 2 秒一镜，切点落不落在拍上）
- 亮度在不在目标时间段

它**不**证明：配色是否好看、运镜是否有戏、表演是否成立、字幕是否压画面。

⚠️ 实测教训：把「色块对了」当成「片子对了」，是这一环最大的坑。
色块能把**结构性错误**提前暴露（顺序/景别/时长），但审美判断只能等真图出来。

占位必须写清楚，比如：

> 格 17/18 是站姿顶替坐姿、格 14 是正面顶替背影、格 3/4/8 是程序画的方块手、
> 人物统一单色看不出表情、背景是色块不是成图。

## 六、别试清单

| 试过 | 结果 |
|---|---|
| 拿 `cv2.imread` 读中文路径 | **静默返回 None**，不报错。一律 `cv2.imdecode(np.fromfile(p, np.uint8), 1)` |
| 在 3 通道 float32 图上 `cv2.ellipse` 传 int 元组做颜色 | `Overload resolution failed`，报错还说 "missing required argument 'color'"。颜色必须 `tuple(float(v) for v in col)` |
| 拿单人立绘直接并排比「耳朵大不大」 | 脸宽差 2.3 倍（143 vs 331px），结论会**反**。必须先把脸缩到同宽再比 |
| 用总帧数对不对来验音画同步 | 删掉镜头空档再补帧，总数照样对得上，但顺序已错 |
| 给整体乘亮度系数来提亮 | 把已经高调的格推爆（p90 305） |
