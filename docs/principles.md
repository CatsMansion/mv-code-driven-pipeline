# 原则：代码怎么长出「手绘动画的语法」

一句话结论，先给：

> **主体是「用代码实现手绘动画的语法」，不是「让方程自己长出画面」。**
> 生成艺术（noise field / 反应扩散 / 波场）只是过场和抽象段的一个工具箱格子。

这条踩过一次大坑，见 §4。

---

## 1. 分层：谁在哪一层

```
song time t ─┬─► SCENE   Canvas2D 1920×1080：角色、遮罩、摄像机、粒子
             ├─► TEXT    排版 / 歌词 / HUD（透明）
             └─► FG      角色画在歌词**前面**（透明）→ 歌词从身体后面穿过
                    ↓
              WebGL2 post：line boil · palette LUT · bloom · CA · glitch · grain · flash
```

⛔ **场景类后处理（boil / glitch / CA / LUT）只作用于 scene 与 fg，永不碰 text 层。**
碰了，文字就永远不可能锐利 —— 而文字在这类 MV 里是画面主体，不是字幕。

## 2. 十条手绘语法（按重要性）

### 2.1 コマ打ち（Koma）— 手绘感的技术来源

- 绘制元素（角色、字形揭示、线条抖动）跑 **12fps**（2s 拍子），影视感要 8fps（3s 拍子）
- 摄影机、光、粒子、颗粒跑**全帧率**
- **在副歌强拍上把绘制层切到全帧率**，运动就"打开"了

全部 30fps 匀速 = 数字感。这是最便宜、最有效的一条。

### 2.2 Line boil — 线条抖动

12fps 重新播种的低频位移 **0.7–1.6px**。干净排版镜头设 0。
没有它，线条像矢量图；有了它，像画的。

### 2.3 文字是画面主体

不是"一张图 + 一行字幕"。是：不同字号、不规则位置、旋转、**被角色遮挡**、
助词缩到 72–80%、行首字放大到 115–130%。

### 2.4 克制，然后爆发（restraint then bursts）

- **≥ 3 个 full holds（≥ 2 小节几乎不动）**。静止才让爆发读得出来。
- 一直在动 = 没有爆发，因为一直在爆。
- budget：每镜 **1 个 screen effect + 1 个 decoration**。颗粒/纸纹可以常开——它们是胶水。

### 2.5 文字从角色身后穿过

角色画进 fg 层 ⇒ 歌词从身体后面穿过去。层次感最高的一招。
实现成本：一个 `fgChar` 开关 + 一次分镜重排（字幕必须和人物**重叠**才有意义）。

### 2.6 色彩要有角色分工

`ink → shadow → mid → accent(≤8% 画面) → hot → glow → highlight`
再加 `afterimage`（补色，做残像）和 `duotone` 对（ink ↔ glow，对比 ≥ 7:1）。

三个颜色打天下，画面一定是"平"的。

### 2.7 字体角色化

| 角色 | 用途 | 1080p 字号 |
|---|---|---|
| R1 Monument | 巨型单字、标题，可裁切（見切れ） | 1200–1700 |
| R2 Lyric mincho | 抒情、竖排 | 96–120 |
| R3 Lyric gothic | 冲击、slam | 96–120 |
| R4 Hand | 记忆、内心话 | — |
| R5 Signal | 时间码、HUD | 20–24 |

规范：**≤ 3 字族/段，≤ 2 字重/镜；绝不合成 CJK 粗体/斜体**（要加载真字重）。

### 2.8 竖排的标点规则

`ー―…〜（）「」` 旋转 90°；`、。` 移到右上 `(+0.5em, −0.5em)`；小假名 `(+0.1em, −0.1em)`。
细节不做，排版永远"死"。

### 2.9 声音对齐的精度

| 项 | 值 |
|---|---|
| 文字出现 | 提前 **0.1–0.2s** |
| 笔画"写好"的时刻 | 落在 onset 上 |
| 切点 | 落在**拍帧或前一帧** |
| 闪光 | **在**拍帧上 |
| hook | 从 pickup 起，视觉冲击落 downbeat |

### 2.10 转场从镜头内部长出来

A 镜头的圆 → B 镜头的同一个圆（iris match-cut）；栏杆、列车、翻页去擦除。
硬切 + 白闪是"装饰"，不是"叙事"——但**遮罩类镜头之间只能硬切**（见 pitfalls §2）。

## 3. 递进的本质：改「质」，不是改「量」

同一批素材做"第二次更狠"，只有三层改动观众能看见：

| 层 | 手段 | 幅度 |
|---|---|---|
| **景别** | hFrac | 每镜推近 **15%** |
| **色彩** | exposure / saturation / 边色 | +0.04 / ×1.08 / 换更浓的色 |
| **结尾** | 同位置的**反向动作** | 闭合 → 撑开 + 白闪 + 硬切黑 |

⛔ 数值微调在 8bit、大画面下**不可见**。±8% 的带宽差 = 白做。

「更痛」不是更灰，是**更亮更浓**。

## 4. 曾被自己带偏的一条（留档，别再犯）

我写过：「真正高级的是让方程自己长出画面，作者预测不了第 300 帧。」

**这个判断把问题带偏了。** 它把"确定性"当成了缺点。实际：

| 追求 | 真正目的 |
|---|---|
| 纯函数 `f(t)`、seeded noise、闭式粒子、无挂钟 | 让 agent 能审查、多 worker 能并行、4 分钟 MV 能 4 分钟重渲 |
| 生成艺术（curl noise / 反应扩散 / 二维波场） | 只是过场与抽象段的工具箱一格 |

**确定性不是"可预测"，是"可重放"**。重放能力决定了迭代速度，而迭代速度决定了质量。

## 5. 开工前的四条自检

1. 画面背后有没有一个**非视觉的内核**（数据 / 频谱 / 结构 / 文本机制）？
2. 静音之后，画面还有没有自己的生命？
3. 随机跳到第 N 帧，我能不能预测它？（**能预测 = 失败**）
4. 6 秒里有几个视觉事件？（**< 10 个 = 密度不够**；标准是每 0.3–0.5s 一个）

这四条不是审美问题，是**可验证**的问题。第 3 条尤其狠：它逼你承认自己是不是在做"数字化的手工设计"。

## 6. 风格自检矩阵

同一作者做第二支片时，逐轴比较，**重合 ≤ 3 轴**才算换了片：

`world / palette / 主形状 / 材质 / 线条 / 排版 / 3D 角色 / 时间结构 / 光 / 运动语法 / 剪辑密度 / 文字机制`

只做"换配色 + 换场景"的，一眼就能看出是同一支片。
